# Clarify

Rewrite tool and dashboard copy so the next action is obvious. Product terminology stays. This pass does not invent claims, and it does not restyle the window.

## When

Labels say Submit, OK, or Click here. Errors name an internal code and stop. The same object has two names. An empty state describes the feature instead of the action.

## Procedure

1. Read the path, not one string. APP.md owns the nouns. If a term is domain language, keep it. Ask before changing a factual claim.
2. For each state, one fact, then the next action, then only the context that changes the decision. Say it once.
3. Buttons name the verb and the object ("Save draft", "Delete the selected run"). Destructive actions name the consequence. Prefer undo when recovery is safe.
4. Errors say what failed, why if the system knows, and how to recover. Empty, no-results, permission, and failure stay distinct. See [first-run.md](first-run.md) for where that text sits.
5. Keep strings whole so a translator can reorder them. Allow the text to grow. Do not concatenate a sentence from fragments.

## Refuses

- Jokes on a destructive or blocking error.
- A new tone that fights the product's vocabulary.
- Placeholder text used as the only label.
- Color or an icon as the only carrier of the message.

## Verify

Read the path at the platform chrome size and with a string about 40 percent longer. The control's accessible name matches the visible label. Hand off to `polish`.
